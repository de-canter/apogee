**Architecture:** Everything hangs off `defineDimensions(shape)`: it yields the Zod schemas for `conditions` (array-of-allowed-values per dimension) and `facts` (one value per dimension), and a prose description the parser and suggestion prompts embed. Rules match facts deterministically; structured checks run against a subject object without a model; the LLM layer runs only when checks pass and an instruction exists, through `@de_canter/apogee-ai`'s `generateObject` with prompts registered in `@de_canter/apogee-prompts`. Model output that a human might overrule (parsed rule, suggested rule) is a kernel `Assertion` with `source.kind = 'ai'` and a confidence. Storage and audit are ports with in-memory implementations. The admin assistant is a composition: `createAgentSession` + `ruleTools(...)` + `memoryTool`, and the rental desk consumes the same store through `rulesContributor`.

**Tech Stack:** TypeScript strict, Zod 4, Vitest 4, tsup; `@de_canter/apogee-{kernel,ai,prompts,agent}` workspace deps. Demo: Next.js 16 App Router in `de-canter/apogee-build`.

## Global Constraints

- Package `packages/rules` (`@de_canter/apogee-rules`), same toolchain as `packages/agent` (tsup dual build, vitest with v8 coverage, `@types/node`, ESLint flat config at the root: `import type` for type-only imports, `ignoreRestSiblings`, no `any`, `exactOptionalPropertyTypes` on so optional keys are spread conditionally).
- No network in tests: every LLM-backed function is tested with `createFakeModelClient([{ object: … }])`; its `generateObject` validates the scripted object against the schema, so the tests pin the output schemas.
- Domain vocabulary is injected: the package ships no enum of document types, statuses, categories, or triggers. The only built-in enums are the check operators, diagnostic severities, conflict types, and suggestion sources (mechanism vocabulary).
- AI output enters as an `Assertion` (`parseRule`, `suggestRules`); confirmation is `confirmRule(parsed, by)` and is recorded in provenance.
- Prompts: five `definePrompt`s in `prompts.ts`, versions `1.0.0`, names `rules.parse-rule`, `rules.validate-rule`, `rules.detect-conflicts`, `rules.suggest-rules`, `rules.evaluate-gate`; `rulesPromptRegistry()` registers them. Prompt text is domain-neutral; the host passes `domain` (a phrase such as "an equipment rental company"), `categories`, and the dimensions description.
- Dates are `ISODate`; durations are numbers of milliseconds; nothing stored is a `Date`.
- Errors: a `RulesError extends Error` with `code`; model errors propagate (a gate never fails open silently). The loader is the one place a store failure is absorbed, and it surfaces the error in `status().lastError`.
- Deviations from the reference product, decided here: `hasActiveOrder` and every other product dimension become host dimensions; `all_tasks_complete`, `document_type_exists`, `date_within_days`, `tolerance_within`, `field_populated` operators are dropped (product logic) and `gte`, `lte`, `neq`, `max_count` are added; condition overlap is "every shared key intersects" (the reference product's "any shared key intersects" is wrong); the fs-watch hot reload is dropped (the loader exposes `invalidate()`); `Assertion.object` is the `Rule` and ambiguities travel beside it in `ParsedRule` because `Provenance` has no free-form slot.
- Branch `feature/b3-rules` in `de-canter/apogee`, commit per task, PR to `main`; after merge tag `rules-v0.1.0`, run `release.yml` for it. Demo work on `feature/rules-demo` in `de-canter/apogee-build` (vendored tarball), PR to `main`.
- Definition of done per task: `pnpm typecheck && pnpm lint && pnpm build && pnpm test` unfiltered at the repo root, coverage ≥ 90% lines for `packages/rules`.
